# 05 — Visualization with ParaView

This document describes the visualization workflow used to inspect FLASH simulation results after conversion to VTK ImageData (`.vti`) format.

ParaView was used as the primary visualization tool because it provides interactive rendering, animation, slicing, volume visualization, and quantitative analysis capabilities for large scientific datasets.

---

## Objective

The objectives of visualization were to

- Verify that the FLASH simulation evolved correctly
- Inspect the spatial distribution of physical variables
- Observe the evolution of the Sedov blast wave
- Validate the yt-to-VTK conversion pipeline
- Prepare the workflow for future scientific analysis

---

## Representation Modes

ParaView provides multiple rendering representations.

### Surface

Displays the external surface of the computational domain.

Useful for observing scalar coloring across the dataset.

---

### Wireframe

Displays the computational mesh.

Useful for verifying domain geometry and exported grid resolution.

---

### Surface With Edges

Displays both the scalar field and mesh boundaries.

Useful for checking grid discretization.

---

### Volume

Available for genuine three-dimensional datasets.

Since the current simulation was compiled in 2D, volume rendering did not reveal an actual volumetric explosion.

## Animation

Each FLASH plot file represents a snapshot in simulation time.

Opening multiple `.vti` files as a time series allows ParaView's animation controls to display the temporal evolution of the blast wave.

The observed evolution showed

- initial energy deposition
- outward propagation of the shock front
- increasing shock radius over time

The expanding wave remained radially symmetric throughout the simulation.

---

## Verification of the Simulation

Visualization confirmed that

- the yt conversion pipeline worked correctly
- all exported scalar fields were valid
- no obvious numerical artifacts were present
- the Sedov blast evolved smoothly over time
- adaptive mesh refinement was sampled correctly onto a uniform grid

This provided confidence that both the FLASH simulation and the post-processing workflow were functioning as intended.

---

## Important Observation

Although ParaView displayed the simulation successfully, the blast wave appeared only on a single face of the computational cube.

Instead of observing a spherical explosion occupying the full volume, the solution appeared as a two-dimensional circular shock embedded within a thin three-dimensional slab.

Inspection of the FLASH build configuration identified the cause:

```text
DN_DIM = 2
NZB = 1
```

The executable had been compiled as a **two-dimensional** simulation.

Consequently,

- FLASH solved the hydrodynamic equations only in the x–y plane
- the z-direction contained a single computational layer
- ParaView correctly rendered the dataset as a thin slice rather than a true volume

This confirmed that the visualization software and conversion pipeline were functioning correctly; the limitation originated from the simulation build itself.

---

## Lessons Learned

This visualization exercise demonstrated several important aspects of scientific post-processing:

- Successful visualization does not guarantee the intended simulation dimensionality.
- Verifying dataset metadata is as important as inspecting the rendered output.
- ParaView serves as an effective validation tool for identifying issues in simulation setup.
- The combination of FLASH, yt, and ParaView forms a robust workflow for computational fluid dynamics studies.
